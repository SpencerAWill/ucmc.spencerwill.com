# R2 key prefixes

Part of the data rule; `data/core.md` covers the two buckets.

## R2 key prefixes

A prefix is agreed by three places — the minting helper, the URL-stripping helper, and the `routes/api/*.$.ts` route that re-prepends it to read from R2 — plus `GC_PREFIXES` in `server/cron/retention.server.ts`. **Keys are never user-visible, so a prefix outliving its feature's rename is correct**: `album/` is still `gallery/` and sponsor logos are `sponsors/`. Re-keying would mean a copy-then-delete pass over every deployed bucket where a partial run strands objects. A round-trip test pins each pair, because the Album's drifted during a rename and 404'd every photo in local dev. **"Fixing" a stale-looking prefix in `GC_PREFIXES` silently stops the orphan sweep from ever seeing those objects.**

**The private bucket's first prefix is `site-feedback/screenshots/`** (`server/r2/site-feedback-screenshots.server.ts`), one object per report keyed `<sfb_id>.webp|.jpg`. There is no `routes/api/*.$.ts` that re-prepends it: `/api/site-feedback/:id/screenshot` reads `feedback.screenshot_key` from the row after checking the viewer, so the key never reaches the client. The orphan sweep's private pass and the 30-day retention sweep are the other two places that agree on it.

**The private bucket's Album prefixes are `album-originals/<photoId>/<hash>.<jpg|png|webp>` (the raw upload, never served) and `album-full/<photoId>/<hash>.webp` (the metadata-free copy)** (`server/r2/album-originals.server.ts`). Both hashes are the raw original's. As with screenshots, no `routes/api/*.$.ts` re-prepends them: `/api/album-full/:publicId/:file` reads `album_photos.full_key` after checking the viewer. Both sit in the private orphan sweep beside `site-feedback/screenshots/`, which keeps keys referenced by `album_photos.original_key` / `full_key`. **Their age guard is a day (`ALBUM_MIN_ORPHAN_AGE_MS`), not the five minutes screenshots and the public prefixes get**: the PUT happens on pick and the INSERT on Save, and between the two a member is cropping and writing alt text, so a dialog open over the daily sweep would otherwise lose its upload. An upload the member never saves is left for the sweep. Row delete removes all three objects; see `feature-album.md`.
